## 범위와 기준

- 시각 문항 32개 전부의 질문, 보기 세 개, 해설, 보기별 오답 안내 세 개, 문제와 보기의 캡션을 하나씩 읽었다. 캡션이 없는 악보 문항은 문구를 새로 붙이지 않았다.
- 29개는 문구를 수정했고, 3개는 전체 문구를 유지했다. 아래의 `edited`는 적어도 한 문구를 수정했다는 뜻이며, 나머지 문구도 검토했다. `kept`는 모든 문구를 그대로 두었다는 뜻이다.
- 짧은 문장과 구체적인 행동을 썼다. '유지', '대비', '제시', '범위', '경계' 같은 보조 표현은 '그대로 두기', '다르게 하기', '그림', '마지막 음만', '나누는 표시' 등으로 풀었다.
- 음표·쉼표 이름, 음이름, 차례가기·뛰어가기, 셈여림, 말붙임새, 세, 한배 등 학습 용어는 필요한 곳에 남겼다. 음표 머리, 오선, 구음, 덧줄처럼 이해를 돕는 말은 뜻을 설명했다.
- 질문에 그림 속 정답 음표 이름이나 빈칸의 구음을 써 주지 않았다. 개수, 길이, 빠르기, 바꿀 수 있는 자리 등 정답을 가르는 조건을 보존했다.
- ID, 학년, 학습 영역, 정답 번호, 악보의 음·길이·쉼·점·박자, 도표 셀, 배치 설정은 수정하지 않았다. 오디오와 생성된 내보내기 파일은 건드리지 않았다.

## 검증과 남은 위험

- 변경 전 `npm test -- src/quest/bank/visualQuality.test.ts`: 57개 통과.
- 보조 용어 풀이와 여러 조건의 보존을 확인하는 회귀 테스트 두 개를 추가했다. 문구 수정 전 새 테스트 두 개가 실패하는 것을 확인했다.
- 변경 후 같은 명령: 59개 통과. 기존 의미 검증은 유지했고, 기존 테스트에서는 `visual-56-gugak-accent`의 동일 의미 정답 문구 한 곳만 갱신했다.
- 관련 테스트를 파일별로 실행했다. `npm test -- src/quest/bank/visualQuality.test.ts`는 59개, `npm test -- src/quest/bank/visualConceptQuestions.test.ts`는 13개, `npm test -- src/quest/bank/bank.test.ts`는 5개 통과했다. 합계 77개로 악보 계약과 문항집 연결도 확인했다.
- 세 테스트 파일을 한 번에 실행했을 때는 샌드박스 `Temp/.../ssr` 변환 파일을 찾지 못하는 `ENOENT`가 발생했다. 직렬 옵션으로도 재현했으며, 각 파일을 독립 실행하면 모두 통과했다. 테스트 실행 환경은 수정하지 않았다.
- 원본과 현재 문항을 구조적으로 비교해 문구·캡션 외 데이터가 32개 모두 동일함을 확인했다. 검토 기록의 32개 ID와 실제 수정 29개·유지 3개도 대조해 일치함을 확인했다.
- 실제 초등학생 대상 읽기 확인은 하지 않았다. 용어 풀이를 덧붙인 일부 문항은 전체 글자 수가 늘어, 실제 화면의 줄바꿈과 읽기 부담은 후속 확인이 필요하다.
- 이번 범위는 시각 문항 32개뿐이다. 다른 문항과 활동, 전체 앱 화면·오디오 재생은 검증하지 않았다. 생성 JSON과 전체 문항집의 재생성은 상위 작업에서 진행해야 한다.
