## 퀴즈 흐름

8회 × 5문항, 총40회 문항 제시를 검사했다. 중복을 제외한 ID는36개다. 이 검사를 문제은행96문항 전체의 새 내용 감수라고 부르지 않는다.

1. 게임이 끝나면 학년군에 맞는 그림·듣기·개념 혼합5문항이 나오는지 확인했다.
2. 답을 고르기 전 제출이 5/5로 처리되지 않는지 확인했다.
3. 모든 듣기 버튼을 눌러 자연 종료까지 재생했다. 총20회 재생에서 실제 출력 신호를 측정해 무음을 배제했다.
4. 일부러 다섯 답을 모두 틀리게 골라 0/5를 만들었다. 각 문항의 오답별 설명·정답 표시·일반 해설이 해당 데이터와 일치했다.
5. 모든 문항의 배우기 버튼을 눌렀다. 총40건에서 수첩의 학년·단원·제목·도입 내용과 교사용 성취기준이 올바르게 연결됐다.
6. 수첩을 닫으면 결과 퀴즈의 선택 답과 해설이 유지됐다. 답을 고쳐 다시 제출했을 때 8회 모두5/5, 다섯 문항의 정답 해설 표시가 나왔다.
7. 다른 곡 선택 버튼으로 라이브러리에 돌아오고 열린 대화상자가 남지 않는지 확인했다.

## 발견·수정한 문제

기존 배포 `b8e3dd6`의320px 결과창에서 악보 문항이 가로로 넘쳤다. 원인은 fieldset의 기본 min-content 크기와 VexFlow가 호스트·SVG에 넣는 고정 inline 너비였다.390px에서도 악보 일부가 기본 상태에서 내부 스크롤 뒤로 가려질 수 있었다.

사용자가 수정·배포를 승인한 뒤 다음을 적용했다.

- 결과 퀴즈 fieldset의 최소 인라인 크기를0으로 설정.
- 악보 grid 트랙을 `minmax(0,1fr)`로 제한.
- 악보를 그린 뒤 고정 inline 너비·높이를 제거해 기존 반응형 CSS가 적용되게 함. viewBox와 오선·음표 데이터는 유지.
- 확대 상태의650px 악보와 내부 스크롤은 유지하고, 축소하면 전체 악보가 다시 맞도록 검사.

실제 QuizPanel·CSS를 쓰는 별도 배치 fixture로 수정 전 실패를 재현했다. 수정 후96문항 ×320·390·768px =288건과 확대·축소 복귀3건이 통과했다. 이 fixture는 게임 완료나 실제 듣기 검사를 대신하지 않는다.

수정 배포본에서 위8회의 전체 흐름을 처음부터 다시 검사했다. 데스크톱1440×900, 모바일390×844, 결과창320×740을 포함한68건의 대화상자·화면 경계 검사가 통과했다. JavaScript 예외와 관측한 앱 에셋 HTTP 오류는0건이었다.
